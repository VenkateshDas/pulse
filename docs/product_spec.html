3.0 · Unified Disk View redesign

Objective. Collapse the three scattered storage pages — Storage, Clean, and Vault — into one page that answers a user's only three storage questions, in order: "What is eating my disk?" → "What can I safely remove?" → "What did I delete, and how do I free it for real?" One mental model, one legend, one place. No hunting across tabs to understand your own disk.

One page · three lenses · one truth

redesign reuses scan engine real-time

Why

Today storage understanding is split across Storage (treemap), Clean (suggestions), and Vault (undo). The user must mentally stitch three pages together to grasp one disk. The control boundary — what is mine to manage vs. what the system protects — is never shown. Result: hesitation, and the #1 cleaner fear ("did I just break something?") goes unanswered at the point of decision.

What

A single Storage page with three tabs:

Map — hierarchical treemap, drill from disk root / to any leaf. Every cell is colour- and lock-coded by the control axis (below).
Reclaim — one flat list of everything safe to remove across the whole disk, with a single bulk action. The shortcut for users who don't want to drill.
Trash — the real macOS ~/.Trash, hidden dotfiles included. Put Back to restore, Empty to free for real.

Impact

The control boundary becomes the spine of the UI. A four-state legend tells the user, at a glance, what they own:

🔒 Protected — system / SIP / other apps. Pulse cannot touch it. Derived from path, not guessed.
🟢 Safe — caches, logs, derived data. Regenerates. Pre-selected.
🟡 Check first — node_modules, old installers, Downloads. Your call.
👤 Your data — Documents, Photos, Movies. Shown, sized, but never bulk-selectable.

When

The default storage destination from the dashboard and menu bar. Live by design: an FSEvents watcher on the drilled directory refreshes sizes within 300 ms of any add/delete — the map breathes as the disk changes, no manual rescan. Watcher tears down on navigate-up; no subprocess, no polling.

Vault becomes Trash — a deliberate simplification. "Vault" was a second, invented holding area users had to learn. In macOS the holding area already exists and everyone knows it: the Trash. This redesign retires the separate SafetyVault staging dir. Cleaning now moves items to the real Trash via FileManager.trashItem; restore is native Put Back; "Empty Trash" is the one irreversible act that actually frees space. Trade-off accepted: we hand 7-day auto-expiry and exact-path restore to the OS (Finder's "remove after 30 days" + Put Back records) in exchange for honesty and far less code. Supersedes Core Rule "Safety Vault first" and Differentiator ① for the storage flow.
Engine reuse. No new scanner. SafetyGrade (safe / careful / review) already encodes deletability; the redesign adds only a path-derived isProtected() as the fourth state and re-wires the existing StorageScanner treemap, SmartScanner suggestions, and Trash plumbing into one shell. Work is information architecture + a watcher, not a rewrite.
Done when: sidebar shows a single Storage entry (Clean + Vault rows removed) · Map drills root→leaf with all four states visibly distinct · Reclaim bulk-cleans to real Trash · Trash lists hidden files, Puts Back, and Empties with verified freed-bytes · live refresh observable on a real add/delete · SafetyVault and its references deleted with the suite green.

// PulseKit/StorageScanner.swift — protected = derived, never guessed.
// Protected → Pulse cannot/should not move it (greyed, no select).
static let protectedRoots = ["/System", "/usr", "/bin", "/sbin", "/private", "/Library"]
func isProtected(_ path: String) -> Bool {
    if protectedRoots.contains(where: { path == $0 || path.hasPrefix($0 + "/") }) { return true }
    // Not owned by the current user → not ours to touch.
    var st = stat()
    if lstat(path, &st) == 0, st.st_uid != getuid() { return true }
    // SIP-restricted (rootless) flag.
    if (st.st_flags & UInt32(SF_RESTRICTED)) != 0 { return true }
    return false
}
// StorageModel.swift — clean now moves to the real Trash (no Vault).
// trashItem (NOT NSWorkspace.recycle — recycle no-ops on macl bundles).
func moveToTrash(_ paths: [String]) {
    for p in paths {
        try? FileManager.default.trashItem(at: URL(fileURLWithPath: p), resultingItemURL: nil)
    }
    refreshTrash(); rescanCurrentDir()   // live numbers
}
// StorageModel.swift — FSEvents watcher: dir-only, debounced, no subprocess.
private var stream: FSEventStreamRef?
func watch(_ dir: String) {
    unwatch()
    var ctx = FSEventStreamContext(version: 0,
        info: Unmanaged.passUnretained(self).toOpaque(),
        retain: nil, release: nil, copyDescription: nil)
    stream = FSEventStreamCreate(nil, { _, info, _, _, _, _ in
        let m = Unmanaged<StorageModel>.fromOpaque(info!).takeUnretainedValue()
        Task { @MainActor in m.debouncedRescan() }   // coalesce to 300 ms, rescan cur dir only
    }, &ctx, [dir] as CFArray, FSEventStreamEventId(kFSEventStreamEventIdSinceNow),
       0.3, FSEventStreamCreateFlags(kFSEventStreamCreateFlagFileEvents))
    FSEventStreamSetDispatchQueue(stream!, .main)
    FSEventStreamStart(stream!)
}
func unwatch() { if let s = stream { FSEventStreamStop(s); FSEventStreamInvalidate(s); FSEventStreamRelease(s); stream = nil } }
Gotchas — do not skip. ① Empty Trash needs Full Disk Access; removeItem on protected/other-app items throws — only Reclaim-graded (user) items reach Trash, but still surface a skip-count honestly, never a silent fail. ② Put Back has no public API — use in-process Apple Events (Finder, main thread, NSAppleEventsUsageDescription); App Management gates moving other apps' bundles. ③ TCC across rebuilds: test with make dev-cert; ad-hoc rebuilds invalidate grants. Reset stale records: tccutil reset SystemPolicyAllFiles com.pulse.app. ④ Watcher lifecycle: unwatch() on navigate-up and on view disappear — a leaked stream violates the closed-window CPU budget. ⑤ No data-driven animation on the live size deltas — springs only on user navigation, per the core render rule.
Per-phase test gate: make test green · make run visual + functional check on the live app · user approval before each merge (CI green is the floor, not the gate). Update index.md / log.md on phase completion (LLM Wiki).

  • Top-processes panel: 5 processes by CPU, scaleEffect bars (render-only, zero layout thrash)
  • CPU 24H history chart: gap-honest (nil = gap, isolated point = dot, never interpolate); persists to cpu-history.json, survives sleep correctly
  • Greeting with uptime, system load — human-readable context, not raw numbers

Impact

  • Removes the "now what?" moment — the single biggest pain point in monitoring apps
  • Time-to-resolution drops from minutes to seconds for the 80% of common Mac slowdowns
  • Trust builder: user sees Pulse correctly identify the problem → trusts it for cleaning decisions
  • Gap-honest history is a marketing claim: iStat and Stats both interpolate across sleep gaps, showing false trends

When

Primary landing screen when the user opens Command Center. Cause→Fix cards appear only when thresholds are crossed — not as permanent noise. The 24H chart is most valuable the morning after a heavy workday or overnight backup, when the user wants to understand what happened while they slept.

3.5 · Safety Vault — The Moat

UNIQUE IN CATEGORY shipped v0.5 core IP

Why

The #1 reason people don't clean their Macs is fear. Not laziness — fear. "What if I delete something important?" CleanMyMac users have entire Reddit threads about files that shouldn't have been deleted. DaisyDisk has no safety model at all. Trash is permanent after Empty. Safety Vault eliminates the fear category entirely: if everything is undoable for 7 days, cleaning becomes as safe as dragging to Trash. This is the single most defensible feature in Pulse — it's not just better UX, it requires genuine APFS knowledge and a well-designed storage model to implement correctly. No competitor has it.

What

  • All deletions moveItem rename to ~/Library/Application Support/Pulse/Vault/<session-uuid>/ — same-volume APFS rename = instant, zero extra space used until purge
  • Per-session JSON manifest: timestamp, item list, sizes, original paths, safety grades. UI presents these items in a flat, modern file-viewer list rather than rigid session groups.
  • 7-day countdown with configurable window (1–30d); purge order: oldest first when disk is tight
  • Restore/Purge: granular item-level selection with multi-select checkboxes. Dynamic header bar morphs based on selected files (count and size). Collision-safe restores. On partial failure, manifest rewrites with stranded items — never silently loses data
  • Vault size always visible in sidebar footer and dedicated Vault tab
  • "Empty Vault" (or bulk purging selected items) is the only irreversible action in the app — gets the one warning modal
  • System Trash integration: shows Trash size/count, Empty Trash action, "files in Trash haven't freed space yet" education

Impact

  • Eliminates the fear barrier — converts hesitant users into cleaners; cleaning rate increases
  • Every Vault restore = a CleanMyMac horror story avoided — ask those users for App Store reviews
  • Word-of-mouth generator: "Pulse accidentally deleted my DerivedData and I just restored it — amazing" is a better tweet than "Pulse is fast"
  • Structural moat: correctly implementing Vault with collision safety, partial-failure recovery, and APFS-correct sizing is non-trivial — took significant effort, hard to copy quickly

When

Every clean operation, automatically — the user doesn't have to think about it. The Vault is explained once in onboarding ("everything you clean is undoable for 7 days") and then works silently. The Vault tab surfaces when the user is curious or when they need to restore something. The countdown timer creates gentle pressure to confirm the clean was good, which is also a re-engagement touchpoint.

3.7 · Daily Health Journal (shipped v1.0 — repurposed from Storage Timeline)

UNIQUE IN CATEGORY shipped v1.0

Why

The original disk-only timeline showed "Collecting…" for most users on first use (required ≥2 days of data) and provided zero value on day 1. Research across iStatistica Pro, coconutBattery, and Usage (iOS) confirmed that multi-signal daily summaries are the most-valued history feature in Mac utilities. Users want to answer "what did my Mac do on Tuesday?" not just "what was my disk on Tuesday?". The Daily Journal combines disk growth, battery sessions, and notable events into one scannable per-day record and is useful from the very first launch.

What

  • Week Summary card (always shown, even day 1): total disk growth, total and average battery hours this week, latest benchmark score.
  • TODAY card (highlighted with accent border): live disk used + today's delta, battery hours + active time window (e.g. "9:00am–11:30pm"), system uptime. Benchmark event row appears if a run happened today.
  • Past Days card: compact newest-first rows — date, disk delta (▲/▼ with proportional bar visualising magnitude), battery hours + time window, SPIKE badge on >2 GB jumps (tap → navigates to Clean).
  • Disk trend chart: appears only when snapshots.count ≥ 7 — never shown as a useless flat line on day 1.
  • Category breakdown: bottom of page, only when scan data is available from Storage tab.
Data sources (joined per calendar day)
  • TimelineStore — disk snapshots, JSON, 90-day window at Pulse/storage-timeline.json
  • BatteryHistoryStore — battery sessions via DashboardModel.batteryTrend; Entry.firstActiveAt / lastActiveAt supply the time window
  • SystemSnapshot (live) — current disk used and uptime for the TODAY card
  • BenchmarkStore via HealthModel.benchmarkHistory — event annotations per day
Key view-local type
struct DayEntry: Identifiable {
  let date: Date
  let diskTotalBytes: UInt64?
  let diskDeltaBytes: Int64?          // signed; nil for first recorded day
  let categories: [String: UInt64]
  let batteryHours: Double?
  let firstActiveAt: Date?            // battery window start
  let lastActiveAt: Date?             // battery window end
  let batteryCapacity: Int?
}

Impact

  • Useful on day 1 — Week Summary and TODAY card show real data immediately; no dead "building…" state.
  • Multi-signal context: "Jun 12 — disk spike +12 GB AND 12h on battery" narrates the day, not just one metric.
  • Battery session window (9am–11pm) gives lifestyle context no other Mac utility shows.

3.14 · App Uninstaller — Drag to Remove, Vault to Undo

v1.1 (M9) UNIQUE: confidence-graded matches, every uninstall reversible

Why

Dragging an app to the Trash leaves its debris behind — preferences, caches, Application Support, login items, privileged helpers, launch agents. Over years this silently accumulates to gigabytes of dead files for apps the user forgot they installed. Every cleaner ships an uninstaller (AppCleaner, Pearcleaner, CleanMyMac), so its absence is a checklist gap. But the category leaders share one flaw: false positives from naïve name matching. Pearcleaner flagged Google Updater files, unrelated Google apps, and screenshots named "ChromeAI" when uninstalling Chrome; worst case, a substring match on "Chrome" can sweep in personal files. Pulse's wedge is the same as everywhere else in the product: show the evidence, grade the confidence, and stage every move to the Vault so a wrong match is never destructive.

What

  • Two entry points: (1) a large drop zone — drag any .app from Finder/Dock; (2) a searchable list of installed apps scanned from /Applications, ~/Applications, and /Applications/Utilities (icon, name, version, size, last-used date)
  • Identity extraction (zero subprocess): read the dropped bundle's Info.plist for CFBundleIdentifier, CFBundleName/CFBundleDisplayName, and the reverse-DNS vendor prefix (e.g. com.spotify.client → vendor com.spotify)
  • Leftover scan across the known macOS residue locations, both ~/Library and /Library: Application Support, Caches, HTTPStorages, Preferences (*.plist), Logs, Saved Application State, Containers, Group Containers, WebKit, Cookies, Application Scripts, LaunchAgents, plus /Library/LaunchDaemons and /Library/PrivilegedHelperTools; install receipts (/var/db/receipts/<id>.plist, .bom) surfaced read-only for awareness
  • Confidence-graded matching — the core differentiator, mapped onto the existing safety grades:
    • SAFE — exact bundle-ID match (folder/file named <bundle-id> or <bundle-id>.*) or a container the OS itself names by bundle ID. Unambiguous. Pre-selected.
    • CAREFUL — vendor-prefix match (com.spotify.*) or an Application Support / Logs folder whose name equals the app or vendor display name. Listed, never pre-selected.
    • REVIEW — weak name-token match (substring/fuzzy). Surfaced for awareness only, never bulk-selectable — this is the tier that catches the "Chrome → personal file" trap and refuses to auto-act on it.
  • Every row carries the same evidence contract as Smart Clean: plain-English label, owning-app icon, size, last-modified, an explainable reason ("matched bundle ID com.spotify.client" vs "name contains 'Spotify'"), Finder-reveal, and an expandable file list
  • The app bundle itself is included as the primary SAFE row (its .app), so one action removes app + debris together
  • Uninstall, never rm, split across two reversible stores: the .app bundle goes to the system Trash via FileManager.trashItem (Finder "Put Back" restores it, the familiar mental model for an app — NSWorkspace.recycle was tried first but silently fails on Mac App Store bundles carrying a com.apple.macl sandbox xattr; trashItem does the same rename and works whenever /Applications's parent dir is writable, which it is for admin users even when the bundle itself is root-owned, with a direct ~/.Trash rename as a final fallback); every ticked leftover moveItems into one Vault session (instant APFS rename, restorable for the retention window). This keeps the /Applications hard-floor denylist fully intact — Pulse never moves a system-area path into its own Vault. Honest result line: "AppName moved to Trash · 13 leftovers (1.3 GB) staged in Vault — restore anytime for 7 days"
  • Orphan mode: a second tab scans the same residue locations for files whose owning app is no longer installed (bundle ID resolves to nothing via LSCopyApplicationURLsForBundleIdentifier) — reclaims debris from apps already dragged to Trash the old way
  • Verify step — a post-uninstall receipt (the "Verify" beat of Glance → Understand → Act → Verify): after the action runs, the plan view is replaced by a success receipt, not a one-line status that vanishes. It shows: a green confirmation header ("AppName uninstalled"); the app row marked moved to Trash with the "Put Back in Finder to restore" mental-model hint; an itemized list of exactly which leftover files were staged (label · original path · size) so the user sees what was removed, not just a byte total; a headline total ("14 items · 1.3 GB → Vault"); an honest note for anything skipped (REVIEW items left untouched, or a leftover whose move failed and needs Full Disk Access); and two actions — Restore everything (one click pulls the Vault session back to original locations) and Done / Uninstall another. Removal is confirmed against reality: the app row reflects the actual recycle result, and the staged list is the Vault session's real contents (a row only appears if its moveItem truly succeeded), never an optimistic guess.
  • Full Disk Access recovery: when the app move or a leftover move is denied (a sandboxed location Pulse hasn't been granted), the receipt lists the still-Pending items, explains that Pulse needs Full Disk Access, and offers a Grant Full Disk Access button (deep-links to System Settings → Privacy & Security → Full Disk Access via x-apple.systempreferences) plus a Retry that re-attempts only the failed pieces and merges the new outcome into the same receipt — no need to re-run the whole scan.

Impact

  • Closes the obvious feature-parity gap with every competitor — table stakes for "complete Mac cleaner"
  • Beats the leaders on their weakest point: graded confidence + Vault staging means Pulse can be aggressive about finding leftovers without ever being destructive about removing them — the Pearcleaner false-positive horror story can't happen here
  • Reuses the moat: Vault, safety grades, evidence rows, hard-floor denylist all already exist — high feature value, low incremental risk
  • Orphan scan is a dramatic first-run result — most Macs have residue from a dozen long-gone apps

When

User navigates to the Uninstall tab (new sidebar item) or drags an app onto the drop zone. Scan streams results in <1s — it is a bounded, shallow enumeration of ~20 known directories matched by name, never a full-disk walk. The SAFE tier (app + bundle-ID matches) is pre-selected; the user reviews CAREFUL/REVIEW, ticks what they want, and clicks Uninstall. The .app goes to the system Trash, leftovers to the Vault; the result screen shows both with restore affordances. Hard guards: if the target app is currently running (NSRunningApplication), the action is blocked with "Quit AppName first"; the Vault's isProtected denylist remains the second net at the move boundary, unchanged — the app bundle never enters the Vault, so no denylist exception is needed.

Knowledge Base

  • Per-app rules: bundle ID → which dirs are cache vs data, versioned and signed independently of app releases
  • Community-submittable rules with review gate — compounds into durable moat over time
  • Every grade is explainable: hover → "SAFE because: matches com.spotify.client cache rule v12; directory regenerates on launch"

  • ~/Documents, ~/Desktop, ~/Photos Library, Mail data, iCloud Drive contents — regardless of rules

  • Vault always: every delete is staged — the hard floor is the second safety net, not the first

Known gotchas — read before building

  • Measure CPU with ps -o cputime delta over 60s on a quiet system. Single ps %cpu is lifetime-decayed. Ambient agent/browser load at 40%+ inflates Pulse readings ~6×
  • proc_name() returns empty for other-user processes (launchd!). Fall back to proc_pidpath() basename. Without this fallback, powerd escapes the sleep-assertion allowlist
  • host_processor_info lists efficiency cores first on Apple Silicon; E-count from hw.perflevel1.logicalcpu
  • Stale dist/Pulse.app shadows fresh builds (macOS resume relaunches it). Always pkill -x Pulse before judging UI changes. Confirm with ps -o comm
  • Release builds inline string literals ≤15 UTF-8 bytes (Swift small-string) — strings | grep can't prove short UI labels are present
  • AppleSmartBattery on Apple Silicon: CurrentCapacity is a percentage (MaxCapacity pinned to 100). Intel: raw mAh — scale by MaxCapacity. AvgTimeToFull/TimeRemaining sentinel = 65535 minutes → map to nil, never render "~1092h to full"
  • ISO8601 JSON date round-trip truncates sub-second precision — compare struct fields, not whole Codable structs with Date, in tests
  • First storage scan stalls minutes blocked on TCC (Downloads/Desktop/Documents) with no visible dialog. Later scans ~2s. Addressed by the onboarding pre-flight (FDA deep-link before the first scan)
  • UNUserNotificationCenter.current() traps from a bare SwiftPM executable (no bundle). Guard every notification call with Bundle.main.bundleIdentifier != nil
  • Dashboard layout is non-scrolling by design — fits min window 1080×720, bottom row stretches. Verify after any card addition. KPI cards now carry optional footer stat chips (VitalCard.stats) so CPU/Disk/Thermal match the MEMORY card's legend height — keep them single-line + minimumScaleFactor
  • Per-process CPU% must convert mach ticks to ns. proc_taskinfo.pti_total_user/system are nanoseconds; mach_absolute_time() is mach ticks (≈24 MHz on Apple Silicon, timebase ≈125/3). Dividing task-ns by tick-delta inflates CPU% ~40× on M-series — and looks correct on Intel where the units coincide. Convert the wall delta with mach_timebase_info first (ProcessSampler + MonitorEngine)
  • Never credit "freed" bytes before the delete succeeds. SafetyVault purge does try? removeItem; locked/SIP/read-only files fail silently. purge returns whether the dir is actually gone — credit session.totalBytes only then, or the disk-pressure path reports space it never reclaimed
  • Defense-in-depth at the delete/restore boundary. SafetyVault.isProtected() refuses system locations + top-level user-data roots regardless of scanner grading — a tampered manifest's originalPath must not become an arbitrary-file-placement primitive. It denylists by path, not "must be under home" (which breaks the temp-home test harness)
  • Trash cleans contents, not the directory. Staging ~/.Trash wholesale buries items and breaks Finder "Put Back". SmartScan.expandTrash emits one row per trashed item; the .Trash dir itself is never moved
  • Uninstaller sends the .app to Trash, not the Vault. SafetyVault.isProtected() denylists /Applications wholesale (correct for Clean), so the bundle must not go through stage. Route the .app to the system Trash (Finder Put-Back) and stage only the leftovers — the denylist stays untouched and no scoped exception is introduced. Use FileManager.trashItem, not NSWorkspace.recycle: recycle silently fails (error-free but no move) on Mac App Store bundles with a com.apple.macl sandbox xattr, whereas trashItem performs the same rename into ~/.Trash and keeps Put-Back metadata, with a direct ~/.Trash rename as a last-resort fallback. Moving a bundle out only needs write on the parent dir (/Applications is admin-writable), so root-owned App Store apps trash fine without elevation
  • Display sleep ≠ screen lock. NSWorkspace.screensDidSleepNotification tracks actual display power state; com.apple.screenIsLocked fires on lock screen (display can still be on). Use the former for screen-on/off time tracking. NSWorkspace.shared.notificationCenter closures need explicit OperationQueue.main and (_: Notification) type annotations + captured return values to satisfy Swift 6 type inference
  • CGGetActiveDisplayList returns ordered IDs. Storing them in a Set loses the ordering (built-in comes first). Split into Array (for ordered iteration) + Set (for O(1) membership checks on stale ID cleanup)
  • Don't use abs(String.hashValue) for stable colors. Swift's string hash is per-process seeded (colors churn every launch) and can be Int.min (abs overflow-traps → crash from layout). Use String.paletteIndex (FNV-1a) so the treemap and its legend agree across launches
